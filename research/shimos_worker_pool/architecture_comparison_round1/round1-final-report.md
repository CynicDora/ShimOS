# 第三轮实验一：独立隔离域下的跨域 Zygote 性能结论

日期：2026-10-20。全部实验、源代码和分析保存在本目录；未修改历史原型、内核或飞书。

## 结论先行

在本轮固定 NumPy CPU 配方、串行请求、每任务新建 Bubblewrap 域的受限合同下，**跨域预热 G2 对重复任务具有实测完整时间及 CPU 收益，单次任务则没有稳定收益**。G0 已实现相应的原生创建、授权、真实 wait、取消和 H 接管，获得本轮限定资格，因此主比较不再只依赖跨域 Cold 消融。

正式完成 21 个 VM 实验块、63 个会话、1737 次请求，三组各 579 次数值验证全部通过；0 FAIL、0 BLOCKED。每个 N 只有三个同物理宿主的 VM 配对块。宿主部分窗口有明显 I/O 压力，原型的同步证据写入仍影响延迟；结果是这个完整受测原型的成本，不是无诊断执行器的性能上限。

**不能据此宣布节省净物理内存。** G2 保留模板，提高了根 cgroup 记账内存峰值；离散 PSS 的覆盖也不足以准确比较全系统净物理内存。有限样本中 N=2 首次出现三块都为正的时间收益，但尚不能认定为普遍稳定的回本阈值。

## 1. 实际完成了什么

|组|实际路径|每次必须支付的成本|会话一次性成本|
|---|---|---|---|
|G0 原生冷|Bubblewrap/PID1 创建新的受控 Python，许可后初始化 NumPy|新域、新解释器、NumPy/数据/BLAS 初始化、业务、回收|H/R 启停|
|G1 跨域 Cold|每次新 Z，完整 glibc D 派生 S/W；W 获许可后初始化|新域、新 Z、两次派生、NumPy 初始化、业务、Z 和域回收|H/R 启停|
|G2 跨域 Warm|一个可信 Z 预热；每次新域和 S/W，继承初始化内存|新域、两次派生、业务、域回收和模板完整性检查|H/R、Z 创建及预热、最终真实退出|

三组采用相同 CPython 3.10.12、NumPy 2.2.6、OpenBLAS 0.3.29 单线程 CPU 配方、8 MiB float64 数据与 128×128 矩阵乘法，同一数值实现及独立冷参考。G0 的可信静态 C 启动器不从运行中的 Python 使用错误的 raw clone 路径；G1/G2 保留 candidate D 完整 wrapper。G2 没有缓存业务最终输出。

G2 在仍具有跨域构造资格的可信 Z 中初始化固定依赖，G0/G1 在最终 W 中初始化；最终 W 的声明合同一致，不代表初始化阶段的可信代码范围完全相同。当前 H 正常 RETIRE 依赖可信 R 的 EOF 声明，R 失效接管时才自行 drain；没有继承未接入的 `exec_support_followup` 增强保证。

新源级审查和定向故障资格覆盖 23 个 VM、72 次尝试，全部符合对应合同；其中实际数值成功 45 次，确认未执行 21 次，未观察到业务结果 6 次。故障资格 PASS 不等于业务成功。详见架构 (`architecture-baselines.md`, omitted from this source release)、公平性与资格 (`fairness-and-qualification.md`, omitted from this source release)、资格原始矩阵 (`analysis/qualification-final-01/summary.json`, omitted from this source release)。

正式实验每次只运行一个 4 vCPU、4 GiB KVM，三组在同一 VM 内循环平衡顺序，前一会话释放后才启动下一会话。共同期限在 pilot 后冻结为 240 秒，保留单任务保护，并实际验证三组 H 会话到期清理。N=100 全部完整完成，没有沿用旧 60 秒截断结果。来源和执行顺序见预登记 (`frozen/formal-plan.json`, omitted from this source release)及[实验设计](experiment-design.md)。

## 3. 为什么快，以及没有证明什么

N=100 数据提供以下定位证据。下表为描述性请求/初始化观测中位数；同一会话内请求相关，不是 300 个独立机器样本。各行包含或重叠，**不能相加解释完整时间差**。

|观测，毫秒|G0|G1|G2|口径|
|---|---:|---:|---:|---|
|NumPy 初始化及准入观测|252.40|255.28|262.91|G0/G1 各 300 次；G2 每会话一次，共 3 次；含状态/线程/FD 检查|
|纯数值 outputs()|1.18|1.18|1.65|每组 300 次；G2 在此局部阶段没有更快|
|请求建域至 DOMAIN_READY 接收|28.07|26.93|27.11|含本实现建域控制处理，不是纯 namespace syscall|
|完整业务调用至本次收尾完成|533.40|607.61|209.75|G1 包含该请求新 Z 启停；不能用内部较短域片段替代|

G0→G1 是冷启动结构差异：G1 为每个任务再启动外部 Z，经过 S/W 两次派生、切换及模板检查，最后关闭 Z。当前 G1 比 G0 更贵，没有证据把双 fork 本身说成更快。

G1→G2 同时消除了重复 NumPy 初始化与重复 Z/解释器创建、运行时检查、关闭等成本。减少的并非全部是 NumPy import；初始化观测本身也包含资格检查、数据准备、BLAS 调用与指纹。不得用约 255ms 乘请求数，宣称严格解释全部节省。

G2 仍每次建立并回收独立域，仍执行全部业务与数值验证、授权、真实 wait、EOF、模板完整性检查和 H 验收。约 1–2ms 的数值计算远小于完整请求，而结果验证、诊断和控制成本仍占较大部分。当前证据不能把这些成本全视为可安全删除的工作。阶段原始边界和互不重叠的完整时间分区见性能报告 (`benchmark-results.md`, omitted from this source release)和边界审查 (`docs/measurement-boundary-review.md`, omitted from this source release)。

## 4. CPU、内存与 COW

N=100 完整根 cgroup CPU 中位数：G0 49.679 CPU 秒、G1 55.805 CPU 秒、G2 16.904 CPU 秒。按同 VM 配对，G2 相比 G0/G1 的 CPU 节省比例中位数约 66.0%/69.7%。这是实际较少重复工作，不能仅用 wall 噪声解释；但账本不含只读 observer，H 归属前极短创建片段也不完整，不能称精确整机 CPU。

根 cgroup memory.peak 中位数为 G0 45.46、G1 58.17、G2 61.27 MiB。G2 在执行间保留模板，峰值记账并没有下降。cgroup charge 与 PSS 含义不同，共享页最初记账位置会影响对比，不能把这三个数直接解释为物理内存增量。

N=100 可观察根记账内存时间积分中位数分别约 1360、1935、1024 MiB·s，覆盖各序列约 99.1%–99.7%。但第三块 G2 的积分约 1579 MiB·s，高于同块 G0 的 1508 MiB·s；不能声称内存时间对 G0 每次都更好。这里只对连续有效采样区间积分，没有把缺口补零或外推。

批次 PSS 时间覆盖更低，G2 N=100 约 72.9%–86.6%，短命 S/W 及快速变化会被 100ms 采样遗漏。**系统净物理内存收益仍为 Unknown**。可观察 PSS、共享/私有页、模板增长和 COW 代理完整保留，不能将业务 8 字节写入当作实际 COW 页复制量，也不把各进程不同时刻 RSS/PSS 随意相加。细节见CPU 与内存分析 (`cpu-memory-analysis.md`, omitted from this source release)。

## 5. 失败、扰动和适用限制

1. 开发期 G0 的 PID 预算拒绝处理曾导致 R 意外退出；H 兜底不算 G0 正确，原失败保留，修复后同一冻结版本重新资格。旧 checker 的观察口径失败也保留并与实际产品失败区分。
2. Pilot 反向顺序实验出现数百毫秒变化，主要可定位到 R 证据写入及 H 最终 fsync 等已计费区间；不是稳定的 observer CPU 开销估计。本轮没有从正式耗时中减去这些时间。
3. 正式 21 个 VM 的 1538 次宿主采样显示 I/O some avg10 最高 90.58%，memory some 最高 20.17%；N100 第三块尤其有压力。它们可能包含实验写入及外部负载，不能据整段 VM 数据归因某一组，也不能将宿主时间戳直接与 guest 相减。没有删除较慢块或挑选安静重跑。环境账本 (`analysis/formal-host-environment.json`, omitted from this source release)。
4. Z 的计时缓冲已改为有界流式；但 R 的结果列表、资格/数值证据仍随 N 增长，完整控制面不是常数内存。不能把 R 增长说成 Z 泄漏，也不能以 Z 稳定推导无限长期稳定。
5. 安全范围是固定可信单线程 NumPy/OpenBLAS、自有模板、单活跃请求、H 正常存活、私有 VM 与普通受控文件系统。没有 H 死亡、宿主 OOM、并发、任意依赖、多线程 BLAS/GPU 的通用保证。
6. 每请求/业务限额对齐，G1/G2 另有模板限额，但没有三组统一的全系统硬预算；不能推导相同总内存预算下的吞吐优势。没有在线 LLM 或 Agent 调用分布，不能宣称完整 Agent 加速。

## 6. RQ1–RQ7 的直接回答

**RQ1：G2 相比真正的 G0 是否更快？** 在本轮 N≥2 的三个配对块中是；N=1 不是。G0 通过限定共同合同，主比较有效，但存在诊断与宿主压力，不能外推普遍幅度。

**RQ2：G1→G2 节省哪些成本？** 重复 NumPy/数据/BLAS 初始化、解释器/Z 启停，以及伴随的新模板检查与收尾。两次派生和每请求域创建没有消失；收益不能全部算作 import 减少。

**RQ3：何时覆盖一次性成本？** 已采样的首次一致正收益是 N=2；真实连续阈值未测，小样本和 I/O 波动使“稳定 N=2 回本”尚未成立。

**RQ4：CPU 下降了吗，是否有内存代价？** 累计根 cgroup CPU 明显下降，G2 常驻模板和根内存峰值更高。观测内存时间多数改善但并非每块对 G0 都改善；全系统净物理内存收益 Unknown。

**RQ5：是否有稳定的收益转折点？** N1 负、N2 起正是当前观察；N5/10/25/50/100 三块方向一致。只有三个同宿主重复，不能称为已证明的稳定阈值或生产分位。

**RQ6：哪些限制不可省略？** 固定版本、单线程 CPU BLAS 配方、固定输入与工作集、串行、每请求独立域、相同局部预算、正常存活的 H、带验证与证据写入的原型。不同初始化成本、长计算、不同缓存、并发及 Agent 实际需求需要独立证据。

**RQ7：什么支持后续比较域内复用？** G2 仍支付约 27ms 的受测建域片段，以及跨域派生/安全切换、监督和回收。若未来任务安全合同允许复用域，域内机制可能减少这些成本；但本轮明确要求新域，G3 不能在这份主排名中取代 G2。下一轮应先确认“必须新域”与“允许同域”的真实需求，分别定义可比合同，再比较；本轮未实现 G3/G4。

## 7. 下一步只保留有证据的问题

先保留本轮机制与原始负结果，不根据收益重构执行架构。下一次最有信息价值的工作，是控制证据写入与宿主压力后复核完整成本和 N1/N2 的小收益边界，并补足更可靠的物理内存/COW 观测；这不意味着删除安全检查或免费摊销模板。

随后，在明确允许同域复用的独立合同中比较域内 Zygote，才能回答跨域的额外隔离收益值多少成本。本轮没有开发调度器、改变当前项目优先级，亦没有宣称新的系统论文贡献。
