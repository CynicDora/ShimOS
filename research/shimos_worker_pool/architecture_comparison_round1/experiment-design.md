# 实验一：独立隔离域下的跨域 Zygote 对照

本文件在正式性能运行前建立。正式矩阵及最终源码/资格摘要还将以不可覆盖的 `frozen/formal-plan.json` 固定；本文件不能代替该清单。

## 研究问题与比较边界

每个请求都创建并销毁一个新 Bubblewrap 域。G0 是域内直接启动固定 Python 的原生冷路径；G1 每次启动新的外部冷 Z，经过 Z→S→W 后在 W 中初始化 NumPy；G2 一次预热 Z 后，为每个新域派生 S/W。三组使用同一数值实现、参考结果、运行时闭包和最终业务安全策略。G2 的预热在计时内，最后 Z/H 的退出也在计时内。

本轮不实现域内 Zygote、持久业务 Worker、并发或调度器。G0 是具有明确生命周期合同的新候选，不代表所有原生冷启动实现的性能最优。

## 固定环境与业务

- 一次只启动一个实验 VM；固定 KVM，4 vCPU、4 GiB、`-cpu host`，同一物理宿主。
- 固定 guest kernel、Bubblewrap 0.13.1、CPython 3.10.12、candidate-04 D loader/glibc；NumPy 2.2.6、OpenBLAS 0.3.29 CPU 单线程。
- 沿用已准入的 blas 配方：8 MiB float64 准备数组、固定切片/广播/求和、128×128 float64 矩阵乘法。每次实际计算并与独立冷参考比较；不缓存最终业务输出。
- 任务域 512 MiB、256 PID、4 CPU 配额；业务叶 256 MiB、128 PID、2 CPU 配额。G0 不创建没有实际进程的 transition 叶；其业务限额相同。
- G1/G2 的 template 在 task 外，另有 256 MiB、128 PID、2 CPU 配额；顶层产品 cgroup 不设置共同总上限。本轮是相同每任务预算、同一 VM 内的串行低压成本比较，不是固定总内存/CPU 预算下的吞吐比较。
- 正式请求没有人工 40ms 测试后代。资格测试仍保留后代持有输出管道的用例，真实 wait、EOF、域空、删除目录/cgroup 的逻辑不变。这是一项对称的业务负载选择，不与上一轮含人工等待的成绩直接相减。
- 不清 page cache，不给任何组额外热身。安装只读固定 rootfs/DSO、编译原型及准备独立数值 oracle 是共同部署/实验夹具成本，单列，不算请求执行。Python 创建、NumPy 初始化、域创建和最终回收全部计入。

## Pilot 与共同期限

初始三组 N=10 pilot 用于检查可运行性、计时事件与资源账本。失败和分析器修订保留。旧 60 秒 H 会话期限改为三组共同 240 秒；每请求 8 秒 containment、取消确认期限和 H 强制回收仍保留。资格中用同一参数化 H 的 2 秒期限主动触发到期清理，不能用它冒充正式 240 秒性能样本。

正式冻结前再检查长序列和低干扰采集。240 秒最终是否采用，以 `formal-plan.json` 及长序列 pilot 事实为准；正式开始后不按单个变体临时放宽。

新增候选的资格已在同一冻结版本上完成 23 个 VM、72 个执行尝试：全部满足对应故障/正常合同。其中 45 次产生实际数值结果，21 次确认未执行业务，6 次没有观察到业务结果；后三者不能统称业务成功。资格入口为 `analysis/qualification-final-01/summary.json`，准入条件冻结在 `docs/performance-source-review.json`。该资格限可信 R、正常存活的 H、普通私有目录、单活跃请求；没有继承另一个研究目录中尚未接入的 H 自身死亡或文件系统故障保证。

## 正式样本

N=1、2、5、10、25、50、100。每个 N 三个新 VM 实验块，每块各运行三组新会话：

|块|会话顺序|
|---|---|
|1|G0→G1→G2|
|2|G1→G2→G0|
|3|G2→G0→G1|

共 21 个正式 VM、63 个会话、计划 1,737 个请求。种子 `20261020` 用于预登记 VM 块执行顺序；组内请求串行。一个 Z 连续服务的 N 个请求是相关样本，统计比较以同 VM 的完整序列差为单位；三个 VM 不是三台独立物理机器。

上个会话实际释放全部产品资源后才允许下个会话。所有失败、超时、UNKNOWN 和未执行组保留；不把失败外推成 N 次完成，不删除慢样本，不事后挑选有利顺序。若必须改变代码，建立新版本及资格，不拼接不同版本通过记录。

## 计时与资源账本

所有产品时间戳来自同一 guest 的 CLOCK_MONOTONIC。

1. 主完整序列：`fixture_session_start`（fork H 前）→`session_supervisor_waited`（真实 wait H 返回）。包含 H/R、各组所有 Python/Z 的创建、G2 预热、全部请求、Z 关闭和 H 释放；不含 VM 开机/部署/独立 observer 收尾。
2. 同时报告 `fixture_release`：额外根观察、100ms 残留观察窗口及委派空目录释放的夹具尾段。该诊断窗口不解释为架构必要开销。
3. 完整调用：`numpy_call_begin`→`numpy_call_complete`。G1 包含每次 Z 创建及关闭；另列 `request_begin`→`response_ready` 的域请求区间，不混淆二者。
4. Python/NumPy 初始化、建域、实际业务、wait、EOF、域空、资源删除及回复分别报告。关键路径只使用相邻不重叠边界；内部组件 wall/CPU 不能简单相加。

产品根 cgroup CPU 是可归属的完整 CPU 账本，已包含 H/R、Z、各任务叶；不再加 child/cgroup CPU。各角色 rusage 及短进程采样仅用于分解，缺失注明。观察器 CPU 单列。

计时记录最多保留 128 项，沿已有 stdout 流式导出；同步写入成本仍计时。正式关闭 syscall/ftrace 和 NumPy native callback 审计；保留安全、数值、真实 wait 和模板检查。

资源 observer 在产品 cgroup 外只读采样，不杀进程、不代产品清理。预定间隔 100ms，并保存实际采样跨度/覆盖率。PSS 以同一批次读数及稳定进程身份判断，不相加 RSS；无法观测的短进程或启动前段不填零。cgroup 记账内存积分和近同步 PSS 积分是两本不同的账，均不自动等于净物理内存。

## 测量扰动与分析

另做同 VM、相反顺序的 timing on/off 和 observer on/off 小型诊断；不混入正式成绩，不从正式值扣一个推测的校正量。记录宿主 CPU、内存、I/O pressure。

### 正式登记前的实际决策

五个 admission pilot 已完成：长序列 G1/G2 各 100 次，以及各两块相反顺序的计时/观察器开关对照，合计 26 个会话、248 次请求。N100 完整主序列 G1 为 61.929 s、G2 为 22.431 s；均真实释放资源，因此共同 240 s 期限有足够余量。流式缓冲高水位为 128，未确认写入为 0；G2 的这次 N100 模板 PSS 增长约 4 KiB，FD 不增长。这是短时 pilot 的观测，不是长期无泄漏保证。

开关对照暴露明显反向波动，不能推算固定“无探针校正系数”。例如 N2 的 G2 observer on−off 在两块中约 +863/−787 ms；较大变化主要在请求序列与最终关闭，Z 一次性准备较稳定。当前 evidence/log 经 9p 写出，其开销已计入；原有运行时与数值检查仍保留。因此正式固定 timing=1、100 ms 只读采样，不从成绩扣除估计的诊断成本；保留全部慢样本，对短 N 的收益和回本使用三份配对原始值审慎判断。详见 `analysis/diagnostic-admission-pilots-01/` 与 `analysis/cost-admission-pilots-01/`。

每个 N 提供三组完整原始值、中位数和范围，以及三份同 VM 配对差额。单请求分布是会话内描述性统计。只对实际完整且通过资格的序列判断回本，不宣称生产 p99、普遍显著性或完整在线 Agent 加速。
